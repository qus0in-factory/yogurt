# 계산 규칙 명세 — 0.1.1 · 이슈 #3

수동 입력 MVP(0.1.1)의 금액·통화·거래·손익 계산 규칙. 이 문서는 규칙 확정용이며 구현 코드·테스트 코드를 담지 않는다. 각 예시는 이후 `domain` 레이어 TDD 케이스로 옮길 수 있도록 입력→기대결과 형식으로 쓴다.

## 1. 용어

- 현금: 예수금. 원 단위 정수.
- 수량(q): 보유 수량. Q8 표현(§2).
- 단가: 거래 1당 금액. 원 단위 정수.
- 시세: 평가에 쓰는 단가. 원 단위 정수.
- 거래금액: qty × 단가를 반올림한 원 단위 정수.
- 총원가(c): 해당 자산의 이동평균 누적 원가. 원 단위 정수. 수수료 포함 정책은 §4.
- 평균단가: c ÷ q로 유도하는 표시 전용 파생값. 계산 재사용 금지.

## 2. 금액·수량 표현

- 통화: KRW 단일. 외화 금액 입력은 저장 거부 + UI 안내 "KRW만 지원합니다. 환율을 적용해 원 단위로 입력하세요". 외화 자동 환산은 범위 밖.
- 금액: 원 단위 정수. 내부 산술은 BigInt. 표시·API는 문자열(예: "950950").
- 수량: 8자리 고정소수점(Q8). 내부는 scale 1e8 정수(BigInt), 저장·API·표시는 문자열(예: "1.23456789"). 9자리 이상 입력은 half-up으로 8자리 확정.
- 이 문서의 모든 곱·나눗셈은 표기상 소수 연산이지만 실제 구현은 scale 유지 정수 연산(§9 예제는 결과만 확인).

## 3. 반올림 규칙

원칙: half-up(0.5는 멀어지는 방향, 음수는 절댓값 반올림 후 부호 유지). 반올림 위치는 아래 4곳뿐이며 그 외 단계에서는 반올림하지 않는다.

| 위치 | 규칙 |
| --- | --- |
| 수량 확정 | Q8 초과 입력 → 8자리 half-up |
| 거래금액 | round_hu(qty × 단가) → 원 단위 |
| 실현원가 분배 | round_hu(c × q_s ÷ q) → 원 단위 |
| 표시 | 평균단가·수익률 소수 2자리 half-up |

## 4. 거래 유형별 규칙

공통: 모든 거래는 (종목구분, 유형, 서울 시각, 수량, 단가, 수수료)를 가진다. 금액(단가·수수료)은 원 단위 정수, 수량은 §2 Q8 표현을 따른다. 수수료는 사용자가 원 단위 정수로 직접 입력(자동율 계산은 범위 밖).

- 입금: 현금 += 금액. 금액 > 0.
- 출금: 금액 ≤ 현금이어야 하며 초과 시 거부("잔고 부족"). 기타 상태 불변.
- 매수: 거래금액 = round_hu(qty × 단가). 현금 부족(현금 < 거래금액 + 수수료)이면 거부. 성공 시 현금 -= (거래금액 + 수수료), q += qty, c += 거래금액 + 수수료(수수료 원가 포함).
- 매도: q_s ≤ q여야 하며 초과 매도 거부("보유 수량 초과"). 거래금액 = round_hu(q_s × 단가). 실현원가 = round_hu(c × q_s ÷ q). 실현손익 = 거래금액 − 수수료 − 실현원가(매도수수료는 원가에 포함하지 않고 실현손익에서 차감). 현금 += (거래금액 − 수수료), q −= q_s, c −= 실현원가.
- 전량 매도(q_s = q): 실현원가 = c(반올림 불필요).

평균단가는 항상 c ÷ q에서 다시 유도하므로 §3 반올림 오차가 누적되지 않는다.

## 5. 평가·손익·수익률

- 적용 시세: 평가 시점 t의 시세 = t 이전 최신 등록 시세(시각 ≤ t). 없으면 결측.
- 평가금액(자산) = round_hu(q × t시점시세). 결측이면 "미평가(—)"로 합산에서 제외하고 목록에 경고 표시.
- 포트폴리오 평가금액 = 평가 가능 자산 평가금액의 합. 총자산 = 현금 + 포트폴리오 평가금액.
- 미실현손익 = 평가금액 − c. q = 0이면 평가금액·미실현손익 0.
- 총손익 = 실현손익 누적 + 미실현손익.
- 수익률 = (평가금액 − c) ÷ c, 소수 2자리 표시. 분모 0(총원가 0)이면 "—" 표시·계산하지 않음.
- 매도 시 실현손익은 거래 시점 평가에 포함하지 않는다(이미 실현으로 이중 계산 금지).

## 6. 시간·순서

- 시간대: Asia/Seoul 고정. 저장은 ISO 8601 오프셋 +09:00. 거래일은 서울 달력 일자.
- 동일 시각 안정 순서: 재계산·표시 정렬 키 = (시각 오름차순, 생성 순서 ID 오름차순).
- 거래 수정·삭제는 허용하며, 변경 시각 이후 전체 잔고·c·현금·손익을 위 정렬 키로 전체 재계산해 확정한다. 재계산 결과는 §8 검산식을 만족해야 한다.
- 미래 시각 입력(시각 > 입력 시점의 서울 현재)은 거래·시세 모두 거부.

## 7. 거부·예외 처리 입력→기대결과

| 입력 | 기대 결과 |
| --- | --- |
| 외화 금액 입력 | 저장 거부, "KRW만 지원" 안내 |
| 현금 < 거래금액+수수료 매수 | 거부 "잔고 부족" |
| q_s > q 매도 | 거부 "보유 수량 초과" |
| 확정 수량 0인 거래 | 거부 "수량 0" |
| 단가 0·음수 거래 | 거부 |
| 동시각·동유형·동종목·동수량·동단가 중복 입력 | 거부 "중복 거래" |
| 그 시각 시세 미등록 자산 평가 | 미평가(—), 합산 제외 |
| 시세 시각 > 현재 | 입력 거부 "미래 시세" |
| 시세 0 등록 | 허용(평가 0, 미실현 = −c, 수익률 규칙대로) — 상장폐지 표시 |
| 자산 목록에서 q=0 라인 | 유지, 평가금액·미실현 0, 수익률 — |

## 8. 불변식

- q = 0 ⇔ c = 0. 보유 중(q > 0)이면 c > 0.
- 총자산 = 입금 누적 − 출금 누적 + 총손익(실현 누적 + 미실현).
- c 부분 매도 누적 합 = 초기 c(밀림 없음: 예시 §9.2).
- 출금 후 남는 현금 ≥ 0, 잔고 q ≥ 0.

## 9. 숫자 예제

### 9.1 기본 흐름: 입금 → 매수 → 가격 변동 → 부분 매도 → 출금 (1종 ETF, KRW)

| # | 시각(Seoul) | 유형 | 내용 | 현금 변동 | 현금 잔고 | 수량 누적 | 총원가 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| 1 | 2026-01-05 09:00 | 입금 | 1,000,000 | +1,000,000 | 1,000,000 | 0 | 0 |
| 2 | 09:05 | 매수 | 1,000개 @950, 수수료 950 | −950,950 | 49,050 | 1,000 | 950,950 |
| 3 | 09:10 | 시세 | 1,020 등록(평가) | 0 | 49,050 | 1,000 | 950,950 |
| 4 | 10:00 | 매도 | 600개 @1,020, 수수료 612 | +611,388 | 660,438 | 400 | 380,380 |
| 5 | 10:05 | 출금 | 100,000 | −100,000 | 560,438 | 400 | 380,380 |

거래 #2: 거래금액 950,000, c = 950,000 + 950(수수료 원가 포함) = 950,950.
거래 #3: 평가금액 1,020,000, 미실현 +69,050, 수익률 69,050 ÷ 950,950 = 7.26%.
거래 #4: 매도금액 612,000, 실현원가 = round_hu(950,950 × 600 ÷ 1,000) = 570,570, 실현손익 = 612,000 − 612 − 570,570 = +40,818, 평균단가 380,380 ÷ 400 = 950.95(변동 없음), 평가 408,000, 미실현 +27,620.
거래 #5 후 기대값: 현금 560,438, 평가금액 408,000, 총원가 380,380, 실현손익 누적 +40,818, 미실현손익 +27,620, 총손익 +68,438.
검산: 총자산 560,438 + 408,000 = 968,438 = 1,000,000(입금) − 100,000(출금) + 68,438(총손익).

### 9.2 실현원가 분배 반올림 (Q8·분배 편차)

입력: 매수 3개 @333, 수수료 1 → 거래금액 999, 현금 변동 −1,000, c = 1,000, q = "3".
기대: 매도 1개 → 실현원가 = round_hu(1,000 ÷ 3) = 333, c = 667. 재매도 1개 → round_hu(667 ÷ 2) = 334, c = 333. 전량 매도 → 실현원가 = 333 = c, q = 0.
검산: 실현원가 합 333 + 334 + 333 = 1,000 = 초기 c.

### 9.3 수량 Q8 확정

입력: 매수 수량 "0.123456785" → 기대 Q8 확정 "0.12345679"(8자리 half-up). 확정 후 수량이 0이면 §7 규칙으로 거부.

## 10. TDD 이동 가능 최소 케이스

각 규칙 하나 = 실패 테스트 하나(§7 표 + §9 숫자 예제의 기대열). 우선 순서: 9.2 분배 반올림 → 9.1 흐름 → Q8 확정 → §7 거부 표. 배치는 `src/domain/`(AGENTS.md 실제 운영 소스 일반 경로), 80줄 이하.

# 결과 취합 절차

조정자가 Herdr 에이전트(beam, glm, claude, agy)의 작업 결과를 취합하고 검증하는 절차다.

## 1. 기본 원칙 및 시간 제한

- **외부 작업 제한**: `git checkout`, `commit`, `push`, `merge`, 배포, GitHub 이슈/PR 변경 등 외부 작업은 개별 에이전트에게 맡기지 않고, 사용자가 해당 작업을 허용한 범위에서 취합 및 검증 후 **조정자만** 수행한다.
- **5분 시간 경계**: 모든 wait와 prompt --wait에는 --timeout 30000처럼 60000 이하의 값을 명시하며, 취합 및 검증을 포함한 전체 작업이 5분을 초과할 경우 반드시 사용자의 확인을 받는다.

## 2. 상태 전이 해석 및 완료 판단

- **제출 응답만으로 완료 판단 금지**: `herdr agent prompt` 실행 성공 응답은 텍스트와 Enter 전송 성공만 뜻한다. 이후 실제 working 전환과 최종 산출물을 확인하며, 제출만으로 시작·완료를 판단하지 않는다.
- **상태 해석**:
  - `working`: 작업 수행 중. 단일 대기(최대 60초)하며 상태 전이를 관찰한다.
  - `idle` / `done`: 입력 가능한 상태. 작업 정상 종료를 보장하지 않는다. 시작 후 활동이 관찰됐는지, 요청된 산출물과 검증 결과가 있는지 확인한다.
  - `blocked`: 승인 또는 추가 입력 대기 상태. `get`/`read`로 차단 원인을 파악하며, 승인 UI에 임의로 답변하지 않고 필요 시 사용자 확인을 받는다.
  - `unknown`: 상태 식별 불가. 화면 로그를 직접 읽어 실제 프로세스 동작 여부를 파악한다.

## 3. 결과 수집 및 출력 유실 대응

- **결과 조회**: `herdr agent get <target>`으로 신원·상태를, `herdr agent read <target> --source recent-unwrapped --lines 50`으로 완료 보고와 변경 요약을 확인한다. working 중 alternate-screen 이력 조회가 거절되면 --source visible로 읽는다.
- **임시 문서 fallback**: 터미널 버퍼 유실, CLI 말림 현상 등으로 출력을 온전히 확인할 수 없을 경우, 먼저 idle 상태에서 recent-unwrapped 조회 범위를 늘린다. 그래도 최종 보고가 없으면 해당 에이전트에 임시 디렉터리에 보고를 저장하고 경로만 반환하도록 요청해 읽는다. 이 fallback은 최초 작업 계약에서 강제하지 않는다.

## 4. 타임아웃 및 재전송 방지

- **중복 제출 금지**: 타임아웃이 발생했거나 응답이 늦어진다고 해서 동일 프롬프트를 맹목적으로 재전송(중복 제출)하지 않는다. agent_prompt_stalled도 미전달을 증명하지 않는다. 시작 활동 미관찰과 실행 시간 초과를 구분하고 get/read 및 변경 파일을 확인한 뒤 재시도 여부를 결정한다.
- **사전 실측**: 재시도 전에 작업 대상 파일의 변경 여부, 프로세스 생존 여부를 먼저 실측하고 충돌이나 중복 작업이 발생하지 않도록 조치한다.

## 5. 변경 검증 및 통합

1. **파일 소유권 확인**: 작업 계약에서 지정한 허용 파일 목록만 수정되었는지, 보호 파일(`AGENTS.md`, `CLAUDE.md`, `README.md` 등)이나 타 에이전트 담당 파일 침범이 없는지 확인한다.
2. **diff 검토**: `git diff`를 통해 변경 범위가 요청된 사양 및 아키텍처 규칙을 준수하는지 점검한다.
3. **테스트 검증**: 코드 변경은 관련 단위 테스트와 레이어·80줄 검증을 수행한다. 문서만 변경했으면 링크·형식·지침 적합성을 확인하며 불필요한 코드 테스트를 추가하지 않는다.
4. **최종 통합**: 검증이 완료된 경우에만 성공으로 처리하며, 사용자가 해당 외부 작업을 허용한 경우에만 조정자가 직접 커밋·배포 등을 진행한다. 취합 자체가 외부 작업 권한을 부여하지 않는다.

## 6. 관찰·검증 함정

- `pane wait-output`은 기존 화면 출력도 매칭한다. 재실행 시에는 visible 재독으로 새 출력만 판정한다.
- 시간 제한 래퍼(`timeout` 등)는 실행 전에 해당 OS에 있는지 확인한다.
- 배포 전 빌드 산출물·리디렉트 설정 경로(Vite root 하위 `dist`·`.wrangler`)와 `compatibility_date`를 확인한다.

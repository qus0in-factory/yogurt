# 실패·지연 회고

## 언제 쓰는가

- 작업 실패: 산출물 누락, 잘못된 편집, 도구 호출 없이 종료
- 지연·시간 초과: timeout, stalled, 5분 경계 초과
- 재배정: 작성자 이관, 에이전트 교체, 재시도
- 사용자 정정: 인계 정보 오류, 계약 오류가 드러난 경우
- 같은 원인의 반복이 의심될 때

## 원칙

- 근거 없는 단정 금지. 로그·명령 출력·파일 상태 같은 근거 경로를 적는다. 근거가 없으면 확신도를 낮춘다.
- 사람 비난 금지. 판정 대상은 사람이 아니라 입력·계약·명령·도구·모델 수행이다.
- 분류는 정확히 4개만 쓴다: 작업 실패, 위임 실패, 외부 실패, 기타 실패. 정의와 경계는 [분류 기준](references/categories.md).
- 판정은 확률적 판단이므로 스크립트로 자동화하지 않는다.

## 판정 절차

1. 사실 수집: 시각, 대상, 현상, 관련 프롬프트·명령, 변경 파일, 로그 경로를 모은다. 추측과 관찰을 구분해 적는다.
2. 분류 1개 선택: [분류 기준](references/categories.md)의 판정 순서를 위에서부터 적용한다. 여러 원인이 겹치면 주된 실패 지점 하나만 고르고 나머지는 근거에 남긴다.
3. 확신도 표시: 확정(재현·로그로 확인) / 추정(근거는 있으나 주체·원인 미확인) / 미확인(근거 부족).
4. 영향: 산출물, 일정, 다른 작업, 저장소 상태에 미친 영향을 한 줄로 적는다.
5. 재발 방지 1개: 계약·명령·선행 조건·검증 중 어디를 어떻게 바꿀지 실행 가능하게 적는다.
6. 기록: `docs/retro/YYYY-MM-DD.md`에 아래 형식으로 남긴다. 같은 날 파일이 있으면 덮어쓰지 않고 항목을 추가한다.

## 기록 형식

- 시각: HH:MM:SS(미상이면 미상)
- 대상: 에이전트·모델·조정자·도구
- 현상: 관찰된 사실
- 분류: 4개 중 1개
- 확신도: 확정 / 추정 / 미확인
- 근거: 경로·명령 출력·파일 상태
- 영향: 결과와 범위
- 재발 방지: 다음에 바꿀 행동 1개
- 반영 위치: 스킬·문서 경로, 미반영이면 `후속`

## 팀 분배와의 연결

- 배정 전 최근 `docs/retro/` 기록의 재발 방지 항목을 읽고 작업 계약에 반영한다.
- 실패·지연·timeout·stalled·재배정이 발생하면 이 스킬로 판정하고 기록한 뒤 재시도 여부를 정한다.

# 실패 분류 기준

분류는 다음 4개뿐이다. 판정은 아래 순서로 하며, 먼저 걸리는 항목을 채택한다.

1. 입력·계약·명령이 잘못됨 → **위임 실패**
2. 정상 입력에 작업자가 수행하지 못함 → **작업 실패**
3. 도구·서비스·권한·환경 장애 → **외부 실패**
4. 그 외·근거 부족 → **기타 실패**

## 위임 실패

- 정의: 조정자가 보낸 입력·작업 계약·명령·선행 조건·인계 정보·검증 절차가 잘못되어 실패하거나 지연된 경우.
- 판정 기준: 전송 0건, 문법 오류, 없는 명령·경로, 검증되지 않은 전제, 잘못된 인계 정보, 선행 단계(예: DB 마이그레이션 적용) 누락, 부분 검증만으로 커밋.
- 근거 예시: 명령 오류 메시지, 프롬프트 원문, 설치·설정 화면, 사용자 정정.
- 주의: 작업자가 수행을 못 한 것이 명령 오류의 결과라면 위임 실패로 본다.

## 작업 실패

- 정의: 계약과 입력이 정상이고 도구 환경도 정상인데, 작업자가 요구된 수행(도구 호출, 파일 작성, 완료 보고, 규칙 준수)을 하지 못한 경우.
- 판정 기준: 사고만 출력 후 종료, 도구 호출을 텍스트로 출력, 편집 0건, 같은 입력 재시도에도 미수행, 완료 보고와 산출물 불일치, 규칙 위반 산출물.
- 근거 예시: 작업자 화면 출력, 변경 파일 0건, 동일 계약을 다른 작업자가 완료한 기록, CI 로그.
- 주의: 클라이언트가 유효한 도구 호출을 실행하지 못한 정황이 있으면 외부 실패를 먼저 검토한다.

## 외부 실패

- 정의: 작업자와 위임 내용 밖의 도구·서비스·권한·환경 장애.
- 판정 기준: CLI 비정상 종료, OOM, 네트워크·CI 서비스 장애, 403·권한 부족, 실행기 지연, 샌드박스 무출력 정지, 콜백 전송 실패, 플랫폼 설정 차단.
- 근거 예시: 로그 파일, HTTP 상태 코드, 프로세스 종료 기록, 플랫폼 오류 메시지, 대체 파일 기록.
- 주의: 원인 주체가 확인되지 않으면 확신도는 추정으로 두고, 사람의 의도적 재시작이었다면 기타 실패로 재분류한다.

## 기타 실패

- 정의: 위 셋으로 설명되지 않거나, 판정에 필요한 근거가 부족한 경우. 설계 누락, 미검증 위험, 요구 변경도 여기에 둔다.
- 판정 기준: 원인 미확인, 복수 원인 혼재로 주된 지점을 고를 수 없음, 실패가 아니라 잠재 위험인 경우, 사용자 요구 변경.
- 근거 예시: 설정 diff, 산출물 경로, 재현되지 않는 관찰, 사용자 정정 기록.
- 주의: '기타 실패'를 남용하지 않는다. 근거가 추가되면 1~3 중 하나로 재분류한다.

## 경계 사례 판정

- 명령 오타와 작업자 미수행이 겹침 → 명령이 잘못됐으므로 위임 실패.
- 계약은 정상인데 작업자가 도구를 텍스트로 출력 → 작업 실패. 단, 유효한 호출이 실행되지 않은 증거가 있으면 외부 실패.
- timeout 발생 → 마지막 관찰 지점으로 나눈다. 입력 오류면 위임, 도구·실행기 지연이면 외부, 작업자 무응답이면 작업, 구분 불가면 기타 실패(미확인).
- 사용자 정정 → 전달 정보가 틀렸으면 위임 실패, 요구 자체가 바뀌었으면 기타 실패.
- 재배정 → 최초 실패 원인으로 판정하고, 이관 자체는 실패로 세지 않는다.


## 하네스 분류 예시

- `ttft_admission_refused` 또는 `at capacity` 용량 초과 = 외부 실패. 제한 재시도 소진은 보조 복구 실패다.
- picker 열린 상태 확인 없이 검색·선택 키를 보내거나 최종 모델 라벨을 검증하지 않은 잘못된 자동화 시퀀스 = 위임 실패.
